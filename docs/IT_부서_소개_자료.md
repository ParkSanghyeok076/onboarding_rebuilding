## 1. 시스템 개요

**YURA 온보딩 시스템**은 신입사원의 3개월 온보딩 기간을 체계적으로 관리하고,  
멘토링 효과를 AI로 측정·분석하는 사내 HR 플랫폼입니다.

| 항목 | 내용 |
|------|------|
| 목적 | 신입사원 온보딩 관리 자동화 및 멘토링 품질 데이터화 |
| 사용자 | 신입사원, 멘토, HR 관리자 |
| 운영 기간 | 2026년 1월 ~ 현재 (파일럿 운영 중) |
| 현재 인프라 | Supabase (DB·인증·서버) + Vercel (프론트엔드 호스팅) |

## 3. 핵심 기능 상세 — AI 분석 (ABSA)

### ABSA란?
**Aspect-Based Sentiment Analysis** — 주관식 응답을 읽어 "어떤 측면에서 어떤 감정을 느꼈는지"를 자동으로 분해·분류하는 AI 분석입니다.

### 동작 방식

```
신입사원 설문 주관식 응답 (7개 필드)
        ↓
  Claude AI (Sonnet 4.6)
        ↓
Aspect별 감성 분석 결과 (JSON)
        ↓
  HR 관리자 화면에 표시
```

### 분석 결과 예시

**입력 (박소연 1차 설문 q1_5):**
> "솔직히 처음 2주는 무엇을 배워야 하는지조차 몰랐어요. OJT 계획서가 있긴 했지만 너무 형식적이었고 실제 업무와 연결이 안 됐습니다. 멘토님이 많이 바쁘셔서 질문하기가 눈치 보였고요."

**출력:**

| Aspect | 감성 | 신뢰도 | 인용 |
|--------|------|--------|------|
| OJT 계획의 실무 연계성 | 🔴 부정 | 높음 | "너무 형식적이었고 실제 업무와 연결이 안 됐습니다" |
| 멘토 접근 가능성 | 🔴 부정 | 높음 | "질문하기가 눈치 보였고요" |
| 온보딩 초기 방향 제시 | 🔴 부정 | 높음 | "무엇을 배워야 하는지조차 몰랐어요" |

### 미묘한 표현 처리 예시 (정하은 1차 q3_5)

**입력:**
> "가이드를 너무 잘 주시는 게 문제입니다. 제가 스스로 해볼 기회가 좀 더 많았으면 좋겠습니다."

**분석 포인트:** 칭찬형 표현("너무 잘 주신다") 속에서 실제 개선 요구("자율성 부족")를 감지

| Aspect | 감성 | 판단 근거 |
|--------|------|----------|
| 자율적 업무 시도 기회 | 🟡 약간부정 | 칭찬형 표현이지만 핵심은 자율성 부족에 대한 명확한 개선 요구 |

## 4. 시연 시나리오 (시연 계정 안내)

### 접속 계정

| 역할 | 이메일 | 비밀번호 |
|------|--------|---------|
| HR 관리자 | demo_admin@company.internal | demo1234 |
| 멘토1 (오현준) | mentor01@company.internal | demo1234 |
| 신입사원 (박소연) | demo003@company.internal | demo1234 |

### 추천 시연 순서

1. **HR 관리자 로그인** → 온보딩 현황 대시보드 확인
2. **설문 관리** → 박소연(demo003) 1차 응답 클릭 → **ABSA 결과 확인** (사전 탑재)
3. **시계열 차트** → 강태양(demo006) 선택 → 1차 바닥(2점) → 3차 만점 반전 확인
4. **이메일 초안 생성** 기능 시연 (강태양 1차 분석 결과 → 멘토에게 보낼 피드백)
5. **신입사원 계정 로그인** (demo003) → 설문 응답·OJT 일지 화면 확인

### 시연 포인트 — 차별화 요소

- 단순 설문 수집이 아닌 **AI가 주관식을 읽고 개선 포인트를 자동 추출**
- **3개월 성장 궤적**을 차트로 한눈에 파악 (박소연: 2점 → 5점 반전)
- **위기 조기 감지**: 1차에서 낮은 점수 + 부정 ABSA → HR이 즉시 개입 가능
- 분석 결과를 **멘토/팀장에게 보낼 이메일 초안**으로 자동 변환

announcements       — 공지사항
