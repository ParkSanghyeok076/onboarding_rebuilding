# 사내 인프라 전환 가이드

> YURA 온보딩 시스템: Supabase + Vercel → 사내 서버 전환  
> 작성: 인사기획팀 박상혁 선임 | 2026년 4월

---

## 1. 현재 구조 이해

현재 시스템은 외부 클라우드 서비스 두 곳에 의존합니다.

```
[사용자 브라우저]
      ↕ HTTPS
[Vercel] ──── React 앱 (정적 파일 서빙)
      ↕ HTTPS API 호출
[Supabase]
  ├── PostgreSQL DB  ← 모든 데이터 저장
  ├── Auth           ← 로그인·JWT 토큰
  ├── Edge Functions ← 서버 로직 (Node.js 유사)
  └── Storage        ← 이미지·파일 저장
      ↕
[Anthropic Claude API] ← ABSA 분석 (외부 AI)
```

---

## 2. 역할별 사내 대체 방안

### 전체 대응표

| Supabase/Vercel 역할 | 사내 대체 옵션 | 난이도 | 비고 |
|---------------------|--------------|--------|------|
| **PostgreSQL DB** | 사내 PostgreSQL / MySQL / MariaDB | ⭐ 쉬움 | SQL 거의 그대로 사용 가능 |
| **Supabase Auth** | 사내 LDAP/AD 연동 OR 자체 JWT API | ⭐⭐⭐ 어려움 | 코드 수정 가장 많은 부분 |
| **Edge Functions** | Node.js 서버 (Express/Fastify) | ⭐⭐ 보통 | Deno → Node.js 변환 필요 |
| **Storage (파일)** | 사내 NAS / 파일 서버 / MinIO | ⭐ 쉬움 | URL 경로만 변경 |
| **Vercel (프론트)** | nginx / IIS 정적 파일 서빙 | ⭐ 쉬움 | `npm run build` 결과물 배포 |
| **Claude API** | 외부 API 허용 OR 사내 LLM | ⭐⭐ 보통 | 방화벽 정책 확인 필요 |

## 3. 구성 요소별 상세

### 3-1. 프론트엔드 (가장 쉬움)

**현재**: Vercel이 `npm run build`로 만든 정적 파일을 서빙  
**전환 후**: 사내 웹서버(nginx, IIS, Apache)가 같은 파일을 서빙

```
# 빌드
npm run build

# 결과물 (build/ 폴더)을 사내 웹서버에 복사
# nginx 예시 설정:
server {
    listen 80;
    server_name onboarding.company.internal;
    root /var/www/onboarding/build;
    index index.html;
    location / {
        try_files $uri /index.html;  # React SPA 라우팅용
    }
}
```

**코드 변경**: `.env` 파일에서 API 주소만 사내 서버로 교체
```
# 현재
REACT_APP_SUPABASE_URL=https://xxx.supabase.co

# 전환 후
REACT_APP_API_URL=http://onboarding-api.company.internal
```

---

### 3-2. 데이터베이스 (쉬움, 단 스키마 차이 주의)

**현재**: Supabase가 관리하는 PostgreSQL  
**전환 후**: 사내 DB 서버 (PostgreSQL 권장, MySQL도 가능)

#### PostgreSQL로 전환 시 (권장)

SQL 파일(`/docs/sql/*.sql`)을 그대로 사용할 수 있습니다.

```bash
# 현재 Supabase에서 데이터 내보내기
# Supabase 대시보드 → Settings → Database → Backups → Download

# 사내 PostgreSQL에 복원
psql -U postgres -d onboarding_db -f schema.sql
psql -U postgres -d onboarding_db -f dump.sql
```

**주의 사항**:
- `auth.users` 테이블은 Supabase 전용 → 사내 인증 방식으로 교체 필요
- `gen_random_uuid()` 함수: PostgreSQL 13+ 기본 제공
- RLS(Row Level Security): 사내 DB에서도 지원하지만 인증 방식에 따라 재설계

#### MySQL/MariaDB로 전환 시 (변환 작업 필요)

```
PostgreSQL 타입 → MySQL 타입
uuid       → VARCHAR(36) 또는 BINARY(16)
jsonb      → JSON
timestamptz → DATETIME
boolean    → TINYINT(1)
```

### 3-3. 인증 (가장 복잡)

**현재**: Supabase Auth — 이메일/비밀번호 로그인 → JWT 토큰 발급  
**전환 옵션 2가지**:

#### 옵션 A: 사내 LDAP/Active Directory 연동 (권장)

사내 임직원이 이미 AD 계정(사원번호+비밀번호)을 가지고 있다면 연동 가능.

```
[브라우저] → 사번+비밀번호 입력
     ↓
[Node.js API 서버] → 사내 LDAP에 인증 확인
     ↓
JWT 토큰 발급 → 브라우저에 저장
     ↓
이후 모든 API 요청에 토큰 포함
```

**장점**: 별도 계정 관리 불필요, SSO 연동 가능  
**필요한 정보**: IT부서에 LDAP 서버 주소·포트·조직 DN 확인 필요

#### 옵션 B: 자체 JWT 인증 서버 구축

Supabase Auth를 Node.js로 직접 구현. 현재 구조와 가장 유사.

```javascript
// 로그인 API 예시 (Express)
app.post('/auth/login', async (req, res) => {
  const { email, password } = req.body;
  const user = await db.query('SELECT * FROM users WHERE email = $1', [email]);
  const valid = await bcrypt.compare(password, user.encrypted_password);
  if (valid) {
    const token = jwt.sign({ userId: user.id, role: user.role }, SECRET_KEY);
    res.json({ token });
  }
});
```

### 3-4. 서버 로직 (Edge Functions → Node.js)

**현재**: Supabase Edge Functions (Deno TypeScript, 5개)  
**전환 후**: Node.js Express 서버로 이식

현재 Edge Functions:
```
analyze/          → ABSA 분석 (Claude API 호출)
analyze-objective/→ 객관식 분석 (Claude API 호출)
generate-email/   → 이메일 초안 생성 (Claude API 호출)
register-users/   → 사용자 일괄 등록
reset-password/   → 비밀번호 초기화
```

**변환 작업**: Deno 전용 API를 Node.js로 교체하면 로직은 그대로 사용 가능.

```typescript
// 현재 (Deno)
import { serve } from "https://deno.land/std/http/server.ts";

// 전환 후 (Node.js)
import express from "express";
const app = express();
```

### 3-5. 파일 저장소 (쉬움)

**현재**: Supabase Storage (온보딩 이미지, 공지사항 첨부파일)  
**전환 후**: 사내 파일 서버 또는 MinIO (오픈소스 S3 호환)

코드에서 바꿀 부분: 이미지 URL 경로만 변경
```javascript
// 현재
const imageUrl = `${SUPABASE_URL}/storage/v1/object/onboarding-images/${path}`;

// 전환 후
const imageUrl = `http://files.company.internal/onboarding-images/${path}`;
```

### 3-6. Claude API (AI 분석) — 가장 먼저 확인 필요

**현재**: 서버가 `api.anthropic.com`에 HTTPS 요청을 보내 AI 분석 수행  
**전환 후 3가지 시나리오**:

| 시나리오 | 내용 | 권장 |
|---------|------|------|
| **A. 방화벽 허용** | 사내 API 서버 → `api.anthropic.com` 아웃바운드 허용 | ✅ 가장 빠름 |
| **B. 프록시 서버** | 사내 프록시를 통해 외부 API 접근 | IT부서 정책에 따라 |
| **C. 사내 LLM** | 내부 GPU 서버에 LLM 구축 (llama, Mistral 등) | 장기 목표로 검토 |

**IT부서에 요청할 내용 (시나리오 A)**:
```
아웃바운드 HTTPS 허용 요청:
- 대상 호스트: api.anthropic.com
- 포트: 443
- 요청 주체: 온보딩 시스템 API 서버 (IP: [사내 서버 IP])
```

## 4. IT부서 첫 미팅 체크리스트

미팅 전 다음 정보를 확인하거나 질문으로 준비하세요.

### 확인해야 할 사항

- [ ] **웹서버 환경**: Linux(nginx/Apache) 또는 Windows(IIS)?
- [ ] **DB 서버**: 사내에 PostgreSQL이 있는가? 없으면 MySQL/MariaDB?
- [ ] **인증 방식**: 사내 LDAP/AD를 사용 중인가? SSO가 있는가?
- [ ] **사내망 도메인 발급**: `onboarding.company.internal` 형식의 서브도메인 할당 가능?
- [ ] **아웃바운드 정책**: 사내 서버에서 외부 HTTPS API 호출 가능한가?
- [ ] **파일 저장소**: 사내 파일 서버 또는 NAS 공간 할당 가능한가?
- [ ] **Node.js 설치 가능 여부**: 서버에 Node.js 18+ 설치 가능한가?
- [ ] **HTTPS 인증서**: 사내 CA(인증기관)가 있어 내부 도메인에 SSL 발급 가능한가?

### 요청할 사항

- [ ] 프론트엔드 정적 파일 배포 공간 (nginx 기준 약 50MB)
- [ ] API 서버 실행 공간 (Node.js, 포트 하나 필요)
- [ ] DB 스키마 생성 권한 (또는 IT가 대신 생성)
- [ ] 파일 업로드 저장 경로 (이미지 최대 10MB, 총 용량 협의)
- [ ] `api.anthropic.com` 아웃바운드 허용 (AI 기능 사용 시)

## 5. 전환 단계 개요 (로드맵)

```
Phase 1 (IT부서 협의 후)
  ├── 사내 서버 환경 확인
  ├── DB 서버에 스키마 생성 (docs/sql/*.sql 실행)
  └── Supabase에서 데이터 내보내기 (pg_dump)

Phase 2 (개발 작업)
  ├── Node.js API 서버 구축 (Edge Functions 이식)
  ├── 인증 방식 교체 (Supabase Auth → 사내 LDAP or 자체 JWT)
  └── 환경변수 업데이트 (.env)

Phase 3 (배포)
  ├── npm run build → 사내 웹서버에 배포
  ├── Node.js API 서버 실행 (PM2 또는 systemd)
  └── 파일 저장소 경로 연결

Phase 4 (전환 완료)
  ├── 기존 Supabase 데이터 마이그레이션 검증
  ├── 사용자 계정 이전
  └── Supabase/Vercel 구독 해지
```

## 6. 현재 코드에서 수정이 필요한 파일

전환 시 수정이 필요한 주요 파일:

```
src/lib/supabaseClient.js    ← Supabase 클라이언트 → fetch 또는 axios로 교체
src/lib/edgeFunctions.js     ← Edge Function 호출 → 사내 API URL로 변경
.env                         ← 환경변수 전면 교체
supabase/functions/*         ← Deno → Node.js/Express로 이식
```

## 7. 용어 정리

| 용어 | 설명 |
|------|------|
| **Supabase** | PostgreSQL 기반 BaaS(Backend-as-a-Service). DB·인증·API를 통합 제공 |
| **Vercel** | 정적 파일과 서버리스 함수를 CDN으로 서빙하는 호스팅 플랫폼 |
| **Edge Function** | 서버 없이 실행되는 경량 서버 로직 (Node.js의 클라우드 버전) |
| **JWT** | JSON Web Token — 로그인 후 발급되는 암호화된 인증 토큰 |
| **LDAP/AD** | 사내 임직원 계정을 중앙 관리하는 디렉토리 서비스 |
| **RLS** | Row Level Security — DB에서 사용자별 데이터 접근을 제한하는 정책 |
| **ABSA** | Aspect-Based Sentiment Analysis — 문장에서 측면별 감성을 추출하는 AI 분석 |
| **MinIO** | S3 호환 오픈소스 파일 저장소. 사내 구축 가능 |
