## 1. 프롬프트 비교

### 기존 프롬프트

```
아래는 신입사원의 온보딩 설문 주관식 응답입니다.
각 파트는 응답의 맥락 구분용입니다.
속성명은 파트명을 그대로 쓰지 말고, 텍스트에서 드러난 실제 개념으로 추출하세요.
응답이 없거나 '-', '없음'인 항목은 분석에서 제외하세요.

[멘토링 태도] {q1_5}
[업무 지식 전수] {q2_5}
[실무 피드백] {q3_5}
[조직 적응 지원] {q4_5}
[강점/유지] {q5_1}
[개선 제안] {q5_2}
[자유 의견] {q5_3}

반드시 아래 JSON 형식으로만 반환하세요:
[{"aspect":"실제 개념명","sentiment":"긍정|약간긍정|중립|약간부정|부정","sentiment_score":-1.0,"confidence":"높음|보통|낮음","quote":"원문 발췌","source_field":"q1_5"}]
```

### 변경 프롬프트

```
당신은 인적 자원 관리(HRM) 및 개발(HRD) 전문가이자 숙련된 데이터 분석가입니다.
신입사원의 온보딩 설문 응답을 분석하여, 각 응답에 담긴 세부 속성(Aspect)과 그에 대한
감성(Sentiment)을 추출하십시오.

[분석 지침]
1. 중간 추론(Reasoning) 포함: 각 속성을 도출하기 전, 응답자가 어떤 맥락에서 해당
   표현을 사용했는지 짧게 추론하십시오. 이는 분석의 정확도를 높이는 데 필수적입니다.
2. 속성명 구체화: '멘토링 태도' 같은 파트명을 그대로 쓰지 마십시오. 대신 '피드백의
   구체성', '정서적 지지', '업무 지식의 전문성', '응답 속도' 등 실제 언급된 개념으로
   구체화하십시오.
3. 감성 판단 기준:
   - '중립'은 감정이 배제된 단순 사실 나열이나 판단 유보인 경우에만 부여하십시오.
   - 약간긍정/약간부정은 태도는 보이나 강도가 약할 때 사용합니다.
4. 다중 속성 추출: 한 문장에 여러 속성이 포함된 경우, 각각 분리하여 분석하십시오.
5. 필터링: 내용이 없거나 '-', '없음', '모르겠음' 등 유의미한 정보가 없는 경우는
   JSON 결과에서 제외하십시오.

[입력 데이터]
- 멘토링 태도: {q1_5}
- 업무 지식 전수: {q2_5}
- 실무 피드백: {q3_5}
- 조직 적응 지원: {q4_5}
- 강점/유지: {q5_1}
- 개선 제안: {q5_2}
- 자유 의견: {q5_3}

[출력 형식]
반드시 아래의 JSON 구조로만 응답하십시오. (다른 텍스트는 금지)
[
  {
    "source_field": "q1_5",
    "reasoning": "응답자가 멘토의 태도에 대해 ~라고 언급한 것은 ~에 대한 만족감을 나타냄",
    "aspect": "실제 개념명",
    "sentiment": "긍정|약간긍정|중립|약간부정|부정",
    "sentiment_score": -1.0에서 1.0 사이의 실수,
    "confidence": "높음|보통|낮음",
    "quote": "분석의 근거가 된 원문 발췌"
  }
]
```

## 2. 프롬프트 구조 비교

| 항목 | 기존 프롬프트 | 변경 프롬프트 |
|---|---|---|
| **역할 부여** | 없음 | HRM/HRD 전문가 + 데이터 분석가 |
| **분석 지침** | 2줄 (암묵적) | 5개 명시적 항목 |
| **Reasoning 필드** | 없음 | 필수 포함 |
| **다중 속성 추출** | 명시 없음 (파트당 1개 경향) | 명시적으로 지시 |
| **감성 중립 기준** | 없음 | 명확한 판단 기준 제시 |
| **역설 표현 처리** | 처리 안 됨 | Reasoning으로 맥락 파악 가능 |
| **출력 필드 수** | 6개 | 7개 (reasoning 추가) |
