## 1. PDF 파일명 공백 버그

- **발생 시기**: 2026년 2월
- **상태**: ✅ 해결됨

### 어떤 증상이었나요?
공지사항에 PDF 파일을 첨부할 때, 파일 이름에 공백(스페이스)이 포함된 경우 업로드가 실패하거나 파일을 제대로 불러오지 못했습니다.

예: `2월 신입 안내문.pdf` → 실패
예: `2월신입안내문.pdf` → 성공

### 왜 발생했나요?
인터넷에서 파일 주소(URL)를 만들 때, 공백은 사용할 수 없는 문자입니다.
예를 들어 공백이 들어간 파일명 `내 파일.pdf`를 URL로 표현하면 `내%20파일.pdf`처럼 변환해야 합니다.
이 변환 처리가 누락되어 있었습니다.

### 어떻게 해결했나요?
파일명의 공백을 URL 안전 문자로 자동 변환하도록 코드를 수정했습니다.

## 2. 이미지 재업로드 실패 — 삭제 권한 누락

- **발생 시기**: 2026년 2월~3월
- **관련 파일**: Supabase Storage 권한 설정
- **상태**: ✅ 해결됨

### 어떤 증상이었나요?
온보딩 프로그램 증빙 이미지를 **처음 업로드할 때는 성공**하지만,
같은 항목에 **이미지를 교체(재업로드)하면 실패**하는 문제가 발생했습니다.

### 왜 발생했나요?
Supabase(데이터베이스 서비스)의 파일 저장소에서 파일을 "덮어쓰기(`upsert`)"하는 방식이 내부적으로 변경되었습니다.

**이전 방식**: 기존 파일 위에 그냥 덮어씀
**변경된 방식**: 기존 파일을 먼저 **삭제**하고, 새 파일을 **업로드**함

그런데 파일 **삭제 권한**이 설정되어 있지 않아서, 삭제 단계에서 차단되었습니다.

쉽게 비유하면: 자물쇠가 잠긴 서랍에서 파일을 꺼내야 하는데(삭제), 열쇠(삭제 권한)가 없었던 상황입니다.

### 어떻게 해결했나요?
Supabase 대시보드 → SQL Editor에서 삭제 권한 정책을 추가했습니다.

```sql
-- 사용자가 자신의 이미지를 삭제할 수 있도록 허용
CREATE POLICY "users can delete own images"
ON storage.objects FOR DELETE
TO authenticated
USING (bucket_id = 'onboarding-images' AND auth.uid()::text = (storage.foldername(name))[1]);
```

## 3. SQL 캐스트 문법 오류

- **발생 시기**: 2026년 3월
- **상태**: ✅ 해결됨

### 어떤 증상이었나요?
데이터베이스에서 날짜 계산을 처리하는 SQL 코드를 실행할 때, 아래와 같은 오류가 발생했습니다.

```
syntax error at or near "..."
```

### 왜 발생했나요?
PostgreSQL(데이터베이스 종류)의 타입 변환 문법인 `(값)::text` 방식이
Supabase SQL Editor에서 파싱(해석)되지 않았습니다.

### 어떻게 해결했나요?
1차 시도: `TO_CHAR()` 함수로 교체 → 날짜 타입 불일치로 또 오류 발생
**최종 해결**: 날짜에 숫자를 더하는 방식으로 변경

```sql
-- 변경 전 (오류 발생)
period_1_end = (hire_date + INTERVAL '28 days')::text

-- 변경 후 (정상 동작)
period_1_end = hire_date::date + 28
```

PostgreSQL에서는 `날짜 + 정수`를 하면 자동으로 일수를 더해주는 기능이 있습니다.

## 4. 타임라인 선과 원 정렬 불일치

- **발생 시기**: 2026년 3월 3일
- **관련 파일**: `src/components/OnboardingTimeline` (CSS)
- **상태**: ✅ 해결됨

### 어떤 증상이었나요?
온보딩 진행 현황을 표시하는 타임라인 화면에서,
가로로 그어진 선과 단계를 나타내는 원(노드)의 위치가 수직으로 어긋나 보였습니다.

### 왜 발생했나요?
CSS(화면 디자인 코드)에서 선의 위치와 원의 중심 위치를 각각 계산했는데,
픽셀(px) 단위의 미세한 차이가 발생했습니다.

- 선 위치: `top: 26px`
- 원의 시각적 중심: `14px + 4px + 6.5px = 24.5px`
- 차이: 1.5px 어긋남

또한 오늘 날짜 표시 마커가 선보다 길어서 아래로 튀어나왔습니다.

### 어떻게 해결했나요?
- 선에 `transform: translateY(-50%)` 를 적용해 자동으로 원 중심에 맞추도록 변경
- 오늘 마커를 삼각형(▼) 모양으로 교체

## 5. Vercel 배포 실패 — 미사용 변수 오류

- **발생 시기**: 2026년 3월 5일
- **관련 파일**: `src/pages/AdminOnboarding.js`
- **관련 커밋**: `942e9f5`, `10d36a7`
- **상태**: ✅ 해결됨

### 어떤 증상이었나요?
Vercel(배포 서비스)에서 앱을 빌드할 때 오류가 발생하여 배포가 실패했습니다.

### 왜 발생했나요?
이 프로젝트는 ESLint라는 코드 품질 검사 도구를 사용합니다.
ESLint는 코드에서 **선언했지만 실제로 사용하지 않는 변수**를 오류로 처리합니다.

로컬 개발 환경에서는 경고(warning)로 표시되어 실행이 되지만,
Vercel 빌드에서는 ESLint 오류를 **치명적 오류(error)**로 처리하여 빌드 자체를 중단시켰습니다.

**문제가 된 변수들**:
- `periodStart` — 선언했지만 사용하지 않음
- `periodEnd` — 선언했지만 사용하지 않음
- `p_end` — 선언했지만 사용하지 않음
- `getSurveyIconClass` — 함수를 정의했지만 호출하지 않음

### 어떻게 해결했나요?
사용하지 않는 변수와 함수를 코드에서 모두 삭제했습니다.

> **교훈**: 코드를 수정하다 보면 이전에 쓰던 변수가 남아있을 수 있습니다.
> 배포 전에는 반드시 ESLint 경고가 없는지 확인하세요.

## 6. 직원 등록 401 오류 (register-users)

- **발생 시기**: 2026년 3월 5~6일
- **관련 파일**: `supabase/functions/register-users/index.ts`, `src/lib/edgeFunctions.js`
- **상태**: ✅ 해결됨

### 어떤 증상이었나요?
관리자가 CSV 파일로 신입 직원을 일괄 등록할 때 항상 **401 오류**가 발생했습니다.

**401 오류**란? "당신은 이 작업을 할 권한이 없습니다"라는 의미의 서버 응답 코드입니다.

### 원인 분석 과정 (3단계)

이 오류는 한 가지 원인이 아니라, 조사하면서 여러 겹의 문제가 발견되었습니다.

---

#### 단계 1: 환경변수 URL이 잘못된 프로젝트를 가리킴

**.env.local 파일의 Supabase URL이 틀렸습니다.**

```
잘못된 URL: https://yxkrtcltbdsxx.supabase.co   ← 과거 프로젝트
올바른 URL: https://zpilphcmnvylekzbzuam.supabase.co  ← 실제 운영 프로젝트
```

쉽게 비유하면: 편지를 보내는데 주소가 옛날 집 주소로 되어 있던 상황입니다.

**해결**: `.env.local` 파일에서 URL 수정 후 dev server 재시작

---

#### 단계 2: 수정된 코드가 배포되지 않음

JWT(로그인 토큰) 파싱 코드에 버그가 있었지만, 수정한 코드가 Supabase에 **배포되지 않은 상태**였습니다.
Git 상태로는 `M` (Modified, 수정됨) 표시가 있었는데, 이는 **로컬 파일만 수정되고 서버에는 올라가지 않은 상태**를 의미합니다.

**해결**: `npx supabase functions deploy register-users` 명령으로 최신 코드 배포

---

#### 단계 3: Supabase 게이트웨이의 JWT 검증 실패 (핵심 원인)

가장 근본적인 원인은 Supabase 서버의 **게이트웨이(관문)** 레벨에서 로그인 토큰(JWT)을 거부하는 것이었습니다.

```json
{"code": 401, "message": "Invalid JWT"}
```

**JWT가 뭔가요?**
JWT(JSON Web Token)는 "이 사람이 로그인했다"는 것을 증명하는 디지털 신분증 같은 것입니다.
서버는 이 신분증을 받아서 유효한지 검사합니다.

**왜 유효한 토큰이 거부됐나요?**
Supabase는 최근 JWT 서명 방식을 **HS256 → ES256**으로 업그레이드했습니다.
새로운 방식(ES256)으로 발급된 토큰을, 게이트웨이에서 검증하는 과정에 문제가 생겼습니다.
우리 함수 코드 자체는 정상이었지만, 코드가 실행되기도 전에 게이트웨이 단계에서 차단되었습니다.

**해결 방법**:

게이트웨이의 JWT 검증을 비활성화하고, 함수 코드 안에서 직접 검증하는 방식으로 변경했습니다.

```bash
# --no-verify-jwt 플래그 추가
npx supabase functions deploy register-users --no-verify-jwt
```

그리고 함수 코드 내부에서도 수동으로 JWT를 파싱하던 방식을,
Supabase Auth API를 직접 호출하는 더 안전한 방식으로 교체했습니다.

```typescript
// 변경 전: 수동으로 JWT 파싱 (불안정)
const payload = JSON.parse(atob(payloadB64))
const userId = payload.sub

// 변경 후: Supabase Auth API로 검증 (안정적)
const { data: { user } } = await userClient.auth.getUser()
const userId = user.id
```

**전체 진단 타임라인**:

| 시간 | 발견 내용 |
|------|-----------|
| 1일차 | 401 오류 발생, 원인 불명 |
| 2일차 | `.env.local` URL 불일치 발견 및 수정 |
| 2일차 | 미배포 코드 발견 → 배포 후에도 동일 증상 |
| 2일차 | F12 Response에서 `{"code":401,"message":"Invalid JWT"}` 확인 |
| 2일차 | 게이트웨이 차단 확인 → `--no-verify-jwt` + Auth API 방식으로 전환 → 해결 |

> **교훈**:
> - 오류 메시지를 직접 F12에서 확인하면 원인을 빠르게 찾을 수 있습니다.
> - `{"code":401,"message":"Invalid JWT"}` — 이건 우리 코드가 아닌 Supabase 서버 자체가 반환하는 메시지입니다.
> - Supabase Edge Function을 배포할 때는 JWT 검증 방식을 명시적으로 지정하는 것이 좋습니다.

## 7. 환경변수 URL 불일치

- **발생 시기**: 2026년 3월 6일
- **관련 파일**: `.env.local`
- **상태**: ✅ 해결됨

### 어떤 증상이었나요?
로컬 개발 서버에서 Supabase 관련 기능이 제대로 작동하지 않을 가능성이 있었습니다.

### 왜 발생했나요?
`.env.local` 파일(로컬 환경변수 파일)에 기록된 Supabase URL이 실제 운영 중인 프로젝트 URL과 달랐습니다.
과거에 테스트용 프로젝트를 사용하다가 메인 프로젝트로 전환할 때, 이 파일 업데이트가 누락된 것으로 추정됩니다.

> **참고**: Vercel 배포 환경은 Vercel 대시보드의 환경변수를 사용하므로 영향 없었습니다.
> 로컬 개발 환경에만 해당하는 문제였습니다.

### 어떻게 해결했나요?
`.env.local` 파일의 `REACT_APP_SUPABASE_URL` 값을 올바른 URL로 수정했습니다.

```
# 수정 전
REACT_APP_SUPABASE_URL=https://yxkrtcltbdsxx.supabase.co

# 수정 후
REACT_APP_SUPABASE_URL=https://zpilphcmnvylekzbzuam.supabase.co
```

> **주의**: CRA(Create React App)에서 `.env.local`을 수정한 후에는
> 반드시 `npm start`를 재시작해야 변경사항이 적용됩니다.

## 8. Navbar에 null ~ null 표시

- **발생 시기**: 2026년 3월 6일
- **관련 파일**: Header/Navbar 컴포넌트
- **상태**: ⚠️ 미수정 (기능에 영향 없음)

### 어떤 증상이었나요?
HR Admin 계정으로 로그인하면 상단 네비게이션 바에 이름 옆에 `null ~ null`이 표시됩니다.

### 왜 발생했나요?
Navbar에서 사용자의 온보딩 기간(`period_1_start ~ period_1_end`)을 표시하도록 되어 있는데,
HR Admin 계정은 온보딩 대상이 아니라서 이 값들이 데이터베이스에 저장되어 있지 않습니다(null).
null 값을 그대로 화면에 보여주다 보니 `null ~ null`로 표시됩니다.

### 왜 아직 수정하지 않았나요?
HR Admin의 실제 업무(직원 관리, CSV 업로드 등)에는 전혀 영향이 없습니다.
화면에 약간 어색하게 보이는 것뿐입니다.
향후 HR Admin 전용 Navbar 표시 로직을 별도로 처리할 예정입니다.
